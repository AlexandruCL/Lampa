## For Patrick

The recomputed total is 14,590 credits plus LLM fees whose rate is not stated (17,331 at the cautious music rate), against 18,600 in the concept. It stays under 30,000. It assumes live Talk minutes come with the same Starter subscription, which no page states. Each item's URL and read time are in the matching table row above. Nothing below is decided.

1. **Prices: the official pages disagree on the meter.** `/pricing` uses one shared credit pool, `/pricing/api` says API usage is billed in dollars, and `/pricing/agents` bills call minutes. Which meter the publish script and live Talk draw from is not stated. Changes: the Build 1 publish script's budget guard (credits or dollars) and the Build 2 `canTalkLive` check. Recommendation: buy Starter, since the budget fits under every reading (14,590 credits; or about $1 at API rates, with 6,200 TTS characters against the 75,000 `v3` characters the API table lists for Starter). After the first real publish run, read the usage page in the dashboard to see which meter moved, and write the budget guard against that.
2. **Live Talk is billed in minutes, with LLM fees in credits at a rate not stated.** Starter includes 75 call minutes and 6 concurrent calls. Changes: Build 2 live Talk, and the 4,000-credit reserve. Recommendation: keep the 4,000 reserve as LLM cover until the dashboard shows the LLM rate, and keep the 2-minute cap per conversation.
3. **Music rate disagrees with the Starter allowance.** "900 credits per minute" against "11 minutes of Music" on 30,000 credits (about 2,727 per minute). Changes: the Build 1 waltz. Recommendation: budget the cautious 4,091 until the first take shows the real charge.
4. **`eleven_v3` is now "previous generation"; `eleven_v4` exists at the same API price ($0.08 per 1K characters).** Audio tags are documented for both, and `eleven_v3`'s limit is 5,000 characters, not 2,000. The credit rate for `eleven_v3` by name is not stated (generic 1 credit per character). Whether other models read tags aloud is not stated. Changes: Build 1 persona voices and `scripts/publish-site.ts`. Recommendation: keep `eleven_v3` as the concept says. Comparing it with `eleven_v4` would need a listening test with live credits, so only you can authorise that.
5. **Sound effects: the default model is deprecated and the length limits disagree.** `eleven_text_to_sound_v2` is the default and is removed on 1 March 2027; `eleven_text_to_sound_v3` is newer. Duration limits are 0.5–30 s (API reference), 0.1–30 s (capabilities) and 22 s when set (pricing tooltip). Changes: Build 1 beds, glass, crackle and chime. Recommendation: set `model_id` explicitly in the script; which of the two models is your call. Keep every duration at 22 s or less (15 s and 3 s already are).
6. **Music: the default model is deprecated and the licence terms are unread.** `music_v1` is the default and is removed on 31 January 2027; the quickstart uses `music_v2_5`. The pricing page says "Enterprise use cases include distribution over TV, films, radio and video games" and links `/music-terms`, which is outside my reading list. Changes: Build 1 waltz and the postcard excerpt. Recommendation: set `model_id` explicitly. Read `/music-terms`, or approve opening it, before the waltz is used outside the demo.
7. **React needs a `ConversationProvider`.** "All conversation hooks must be used within a `ConversationProvider`"; Sketch 2 has none. Changes: Build 2 `TalkStation`. Recommendation: wrap the Talk screen in `ConversationProvider`.
8. **Where overrides and dynamic variables go in React is not stated.** The React page puts `overrides` on the hook or provider and does not mention `dynamicVariables`. The JS client passes both to `startSession`, and `@elevenlabs/react` re-exports `@elevenlabs/client`. Changes: Build 2 `start()`. Recommendation: keep `GET /agent/session` and the contract as they are, pass all three to `startSession`, and let the installed package's types settle it. If they reject it, put `overrides` on the provider. No contract change either way.
9. **Overrides must be enabled per field on the agent, or the session errors.** Changes: the Setup agent template. Recommendation: in the agent's Security tab, enable exactly `prompt.prompt`, `first_message`, `language` and the TTS voice.
10. **Language support for `sr` is not stated on the pages I read.** `AgentLang` includes `ro`, `en`, `hu`, `de`, `sr`. `eleven_v3` lists Serbian (`sr`), but I did not read the agent language list. Changes: Build 2 Talk in Serbian. Recommendation: check the language dropdown when the agent is created in Setup; if `sr` is missing, `sr` visitors get tap-to-ask.
11. **A dynamic variable missing at start: behaviour not stated for live sessions.** Appendix A uses `{{persona_name}}`, `{{site_name}}`, `{{visitor_language}}`, `{{persona_traits}}`, which main's `dynamicVariables` and the `AgentSession` schema do not carry. Changes: the Build 1 prompt renderer. Recommendation: have the renderer fill those four into the text before it becomes `overrides.agent.prompt.prompt`, so the contract stays unchanged. Also set `dynamic_variable_placeholders` on the agent for the seven runtime variables, so previews do not show raw `{{…}}`.
12. **Value types for dynamic variables are inconsistent in the docs** ("any JSON value" against "strings, numbers, or booleans only"). Main sends only strings and numbers, so it works under both readings. Changes: nothing. Recommendation: keep it that way.
13. **Blocking tool: the docs now give the field.** `expects_response: true` ("Wait for response" in the UI), and `response_timeout_secs` defaults to 20, range 1–120, or -1 to wait indefinitely. Changes: Build 2 `start_colour_catch`. Recommendation: `expects_response: true` with 120 s, not -1, so a visitor who walks away does not hold the session open.
14. **`onMessage` also delivers tentative transcriptions and debug messages; the payload shape is not stated.** Changes: Build 2 captions. Recommendation: show only final messages, using the installed package's types to tell them apart, without a live call.
